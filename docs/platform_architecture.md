# 렌트카 개인화 플랫폼 설계

> 사장 관점에서 바라본 데이터 기반 개인화 플랫폼 청사진

## 비전

> "데이터를 통해 고객을 이해하고, 개인 맞춤형 경험을 제공하는 렌트카 플랫폼"

---

## 1. 데이터 자산 구조

### 보유 데이터

```
┌─────────────────────────────────────────────────────────────┐
│                      Core Data Assets                        │
├─────────────────────────────────────────────────────────────┤
│  리뷰 데이터             │  예약 데이터                      │
│  - 고객 텍스트 리뷰      │  - 예약 이력                      │
│  - 별점/평점            │  - 차량 종류                       │
│  - 지점 정보            │  - 대여 기간                       │
│  - 작성 시점            │  - 가격/결제                       │
└─────────────────────────────────────────────────────────────┘
```

### 파생 가능 데이터

```
리뷰 → 감성 점수, 키워드, 지점 평판, 불만 패턴
예약 → 고객 세그먼트, 계절성, 선호 차량, LTV
```

## 4. 핵심 서비스 설계

### A. 개인화 추천 엔진

```
Input: 고객 프로파일 + 현재 컨텍스트 (날짜, 위치, 검색어)
     ↓
┌─────────────────────────────────────┐
│  1. 협업 필터링 (유사 고객 기반)     │
│  2. 콘텐츠 기반 (차량/지점 특성)     │
│  3. 벡터 유사도 (임베딩 매칭)        │
└─────────────────────────────────────┘
     ↓
Output: 맞춤 차량 추천, 지점 추천, 프로모션
```

### B. 동적 가격 엔진

```
Factors:
├─ 수요 예측 (예약 데이터 기반)
├─ 계절성/이벤트
├─ 재고 상황
├─ 경쟁사 가격
└─ 고객 LTV (VIP 할인)
```

### C. 리뷰 인텔리전스 (현재 시스템 확장)

```
현재: 지점별 리뷰 요약
확장:
├─ 실시간 불만 감지 → 즉시 알림
├─ 경쟁사 리뷰 비교 분석
├─ 지점 개선점 자동 도출
└─ 고객 VOC → 서비스 개선 루프
```

## 6. 기술 스택 제안

| 계층 | 기술 | 용도 |
|------|------|------|
| 데이터 저장 | Supabase (PostgreSQL) | 관계형 데이터, 고객/예약/지점 |
| 벡터 저장 | Qdrant / Pinecone | 임베딩 검색, 유사도 매칭 |
| 이벤트 스트림 | Redis Streams | 실시간 행동 로그 |
| ML 파이프라인 | MLflow + Python | 모델 학습/배포 |
| API 서비스 | FastAPI | 추천/가격 API |
| 프론트엔드 | Next.js | 고객 앱, 관리 대시보드 |
| LLM | OpenAI / Gemini | 요약, 대화형 서비스 |

### 서비스별 상세 설계

#### A. Core Services (비즈니스 핵심)

```yaml
BookingService:
  책임: 예약 생성/수정/취소, 일정 관리
  API:
    - POST /bookings          # 예약 생성
    - GET  /bookings/{id}     # 예약 조회
    - PUT  /bookings/{id}     # 예약 수정
    - DELETE /bookings/{id}   # 예약 취소
  이벤트 발행:
    - booking.created
    - booking.confirmed
    - booking.cancelled
    - booking.completed

FleetService:
  책임: 차량 재고, 상태 관리, 배차
  API:
    - GET  /vehicles          # 차량 목록
    - GET  /vehicles/available # 예약 가능 차량
    - PUT  /vehicles/{id}/status # 상태 변경
  이벤트 발행:
    - vehicle.status_changed
    - vehicle.maintenance_due

CustomerService:
  책임: 고객 프로파일, 등급, 선호도
  API:
    - GET  /customers/{id}           # 고객 조회
    - GET  /customers/{id}/profile   # 360° 프로파일
    - PUT  /customers/{id}/preferences # 선호도 업데이트
  이벤트 구독:
    - booking.completed → 이력 업데이트
    - review.submitted → 감성 프로파일 업데이트
```

#### B. Intelligence Services (AI/ML 핵심)

```yaml
RecommenderService:
  책임: 개인화 추천 생성
  API:
    - GET /recommendations/vehicles?customer_id=xxx
    - GET /recommendations/branches?location=xxx
  알고리즘:
    1. 협업 필터링 (유사 고객 기반)
    2. 콘텐츠 기반 (차량 속성 매칭)
    3. 하이브리드 (1+2 가중 결합)
  의존성:
    - Vector DB (임베딩 검색)
    - Customer Profile (선호도)
    - Real-time Context (위치, 시간)

PricingService:
  책임: 동적 가격 산출
  API:
    - GET /pricing/quote?vehicle=xxx&dates=xxx
    - GET /pricing/factors?branch=xxx
  가격 공식:
    base_price
    × demand_multiplier      # 수요 계수 (0.8~1.5)
    × season_multiplier      # 계절 계수
    × inventory_multiplier   # 재고 계수
    × customer_discount      # 고객 등급 할인
  의존성:
    - Forecasting (수요 예측)
    - Fleet (재고 현황)
    - Customer (등급/LTV)

ReviewAnalyticsService:
  책임: 리뷰 분석, 인사이트 생성 (현재 시스템)
  API:
    - POST /reviews/analyze
    - GET  /branches/{id}/summary
    - GET  /branches/{id}/keywords
  기능:
    - 감성 분석 (Lexicon + BERT)
    - 키워드 추출 (MeCab)
    - LLM 요약 생성
    - 실시간 불만 감지
```

### 기술 스택 상세

| Layer | Technology | 선택 이유 |
|-------|------------|-----------|
| API Gateway | Kong / Traefik | 오픈소스, K8s 친화 |
| Backend Services | FastAPI (Python) | 비동기, 타입 힌트 |
| Event Streaming | Redis Streams (→ Kafka 확장) | 단순함, Supabase 연동 |
| Primary DB | Supabase | 현재 사용중, RLS |
| Vector DB | Qdrant | 오픈소스, 셀프호스팅 |
